# App 与 Cloud 隔离验收

保护现用设备与 Cloud 数据，用真实应用流程证明功能和同步结果。先确定项目的隔离入口，再执行；不能把 fake provider、HTTP 200 或预期结果写成实服验收通过。

## 找到项目适配

- BeeCount：读取 [references/beecount.md](references/beecount.md)，使用 App 仓的 QA runner；不要在 honeycomb 复制一套执行代码。
- Flutter iOS 与 Python/FastAPI：需要创建或排查适配时读取 [references/flutter-ios-fastapi.md](references/flutter-ios-fastapi.md)。
- 其他栈：查明 bundle/application ID、共享容器、配置加载顺序、持久化目录与同步入口，再按下述约束适配。

## 运行前必须确定的身份

| 对象 | 必须记录与核对 |
|---|---|
| 源码 | App、Cloud 的提交 SHA；含未提交改动时再记录源码内容 hash；使用的 skill 版本 |
| 设备 | 已有设备保护名单；本次新设备的名称、UDID/serial、runtime、run ID |
| 产物 | 构建后的主包和扩展实际 ID、签名权限、共享容器、二进制 hash |
| Cloud | 独立 cwd、配置来源、实际数据库与全部写入路径、新凭证、服务 origin、PID 与启动时间 |

使用仅本次 run 拥有的资源。创建标记、manifest 与私有目录权限；设备操作指定确切设备 ID。应用包、扩展和 App Group 必须独立，不能保留正式 iCloud/共享容器权限。安装前从产物验证，不能只检查工程配置。

Cloud 使用新数据库和新存储目录；排除现用 `.env`、compose volume、默认备份/restore/RAG/rclone 路径与外部服务密钥。读取实际生效配置，在服务 import/初始化写入前拒绝越界路径。使用 loopback 或明确隔离的测试网络。

任何可能重装、替换、清空 App 的操作前，私密备份已存在的数据库、偏好、附件及共享容器。首次安装无数据时也要明确确认应用不存在。Flutter 集成测试可能卸载 App，不得对用户安装的正式包执行。

## 执行闭环

1. 将需求转换成可断言的结果：新增/修改对象的身份、笔数、字段、原数据是否改变；明确未覆盖的平台和场景。
2. 执行项目已有的单元/widget 与同步快速回归，并验证隔离脚本的拒绝路径。快速回归与实服结果分别报告。
3. 新建环境，核对运行时身份；源码有变化时重新生成源码副本和产物，不能沿用旧成功报告。
4. 通过生产 UI 操作被测功能。合成数据可经 fixture 准备；不可直接调用 UI 回调或 Repository 写入来替代被测用户动作。
5. 用实际鉴权、生产同步引擎把 App 变更上传。核对 Cloud snapshot 和实际数据库中的身份、业务字段、关系、标记、币种及笔数。
6. 经真实 Cloud 写接口或实际 web UI 修改，再从 App 拉回并核对。区分“web 写 API 已测”与“web 前端已测”。
7. 根据功能风险补充取消、重复提交/同步、服务故障恢复、共享角色/资源、附件等。故障必须仅影响 QA 服务；明确是服务 503 模拟还是实际设备断网。
8. 切回正常应用入口并重启，确认仍在运行、页面可见、数据持久化。集成入口通过不能替代正常入口验证。
9. 整理脱敏证据；停止本次创建且身份仍匹配的进程和设备，保留私有数据与备份供复查。

## 失败与报告

隔离身份不匹配、无法备份或路径指向现用资源时，停止该操作并报告具体阻碍。业务断言失败时保留失败截图和私有日志，修正后用新源码/环境重跑；不绕过断言，也不将失败标成未执行。

逐项记录 `PASS / FAIL / 未执行`、实际命令与退出码、版本和产物身份、App→Cloud→App 对照、正常入口结果及已知限制。报告只包含合成数据和可公开证据，不提交原始日志、凭证、token、数据库、备份或 App 二进制。

用户授权开 PR 时，将真实验收结果附到 PR；关联涉及的仓和依赖。此 skill 不扩展合并、发版、部署或回复他人的权限；按当前用户指令结束工作。
